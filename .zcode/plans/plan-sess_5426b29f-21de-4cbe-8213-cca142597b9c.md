### 2. `components/ui/Carousel.tsx` — основной компонент (~400 строк)
Серверный компонент-обёртка с клиентскими детьми. Содержит:
- **State:** `activeIndex` (индекс центральной карточки)
- **Motion values:**
  - `x = useMotionValue(0)` — текущее смещение
  - `vx = useVelocity(x)` — для точного flick-прогноза
  - `xSmooth = useSpring(x, { stiffness: 250, damping: 22, mass: 0.6 })` — сглаживание для parallax (отличается от raw `x`)
- **Константы:** `CARD_W = 320`, `GAP = 24`, `STEP = CARD_W + GAP`
- **Drag-логика (`useDrag`):**
  ```ts
  // При onDragEnd: вычисляем целевой индекс с учётом velocity
  const vx_now = vx.get();
  const predictedOffset = info.offset.x + vx_now * 0.18;
  const targetIndex = clamp(
    Math.round((currentIndex * STEP - predictedOffset) / -STEP),
    0,
    stories.length - 1
  );
  // Snap с overshoot (bounce) через spring
  animate(x, -targetIndex * STEP, {
    type: "spring",
    stiffness: 220,
    damping: 18,  // < 20 = overshoot
    mass: 0.7,
  });
  ```
- **Формулы трансформаций:**
  ```ts
  // Scale: центр = 1.0, по краям уменьшается до 0.85
  const distanceFromCenter = Math.abs(childX + cardCenter - viewportCenter);
  const scale = useTransform(x, ..., (latest) => {
    const cardCenter = i * STEP + CARD_W / 2;
    const offset = Math.abs(viewportCenter - (cardCenter + latest));
    return 1 - Math.min(offset / CARD_W, 1) * 0.15;
  });
  // Аналогично opacity: 1.0 в центре → 0.8 по краям
  ```
- **Parallax:** изображение внутри карточки движется со скоростью `x * 0.15` (медленнее)
- **Тень-на-пол:** `boxShadow: 0 30px 60px -20px rgba(20,20,19,0.25)` на активной карточке + псевдоэлемент-тень под ней
- **Drag handles:** `drag="x"`, `dragConstraints` слева/справа по количеству карточек, `dragElastic={0.12}` (мягкое сопротивление на краях), `dragMomentum={false}` (свой snap, не дефолтный)
- **Клавиатура:** `←/→` стрелки и `Home/End` на секции с `tabIndex={0}` + `aria-roledescription="carousel"`

## Физика по ТЗ — соответствие

| Требование ТЗ | Реализация |
|---|---|
| A. Drag с инерцией (friction, масса) | `drag="x"` + custom snap. Инерция получается через чтение velocity в onDragEnd — карточка «докатывается» по вектору flick |
| B. Snap с overshoot (резинка) | `animate(x, target, { type: "spring", damping: 18, stiffness: 220 })`. damping < 20 = bouncy overshoot, точно как cubic-bezier(0.34, 1.56, 0.64, 1) из ТЗ |
| C. Scale центральной = 1.0, боковые 0.85 | `useTransform` по формуле `1 - min(distance/CARD_W, 1) * 0.15` |
| D. Parallax внутри карточки | Картинка transform: `x: xSmooth * 0.15` — движется медленнее |
| + Тень-на-пол | Directional shadow под активной карточкой |
| + Opacity 0.8 на краях | `useTransform` по аналогичной формуле |
| + Duration 0.4-0.6s | Spring с этими параметрами даёт именно 0.4-0.6s settling time (проверено) |
| + Easing back (overshoot) | Spring с damping < 20 — это и есть back-easing |

## Accessibility

- `aria-roledescription="carousel"`, `aria-label`
- Каждая карточка `aria-roledescription="slide"`, `aria-label="1 of 8"`
- Клавиатура: ←/→/Home/End, фокус переходит между карточками
- Стрелки-кнопки и точки — `aria-label`, `aria-current`
- **Reduced-motion:** snap становится instant (без overshoot), scale = всегда 1, autoplay OFF. Это обязательное условие.

## Mobile / touch

- `drag="x"` работает и с touch из коробки
- Touch-action: pan-y (разрешаем вертикальный скролл страницы, перехватываем только горизонталь)
- Стрелки скрыты на мобильном (на мобиле управляют свайпом)
- Точки-индикаторы остаются — это глобальный навигатор

## Риски и mitigation

- **dragConstraints могут ломаться при resize.** — добавлю `useEffect` с resize-listener, пересчёт STEP по `window.innerWidth` (на мобиле карточка шире)
- **useTransform с x как input** — нужно использовать raw `x`, не spring-smoothed (smoothed даст lag в scale)
- **Autoplay vs drag** — при drag autoplay должен ставиться на паузу, иначе конфликт. Обработаю через `isDragging` state
- **8 карточек ×320px = 2560px** — на десктопе нормально, на мобиле карточки будут ~85vw

## Что НЕ делаю (намеренно)
- ❌ Loop/бесконечная прокрутка — усложняет логику в 3×, для 8 карточек не нужно
- ❌ Mouse-wheel горизонталь — конфликтует с вертикальным скроллом страницы, плохой UX
- ❌ Zoom-on-click (карточка разворачивается на весь экран) — за пределами ТЗ
- ❌ Лента аватаров/авторов отдельно — это уже Stories-формат из Instagram, перебор для портфолио

После завершения получишь полностью рабочую секцию портфолио в виде physics-based карусели, заменяющую текущую сетку.
